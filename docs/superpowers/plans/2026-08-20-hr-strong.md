# HR Strong (Solo+) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make staff self-service core on Solo+, reshape `/hr` into a three-panel morning desk, and ship WhatsApp approve sheets, onboarding %, AL/MC balances, and leave↔booking conflict UX.

**Architecture:** Flip `hasStaffPortalAddon` to grant access when the HR pillar is unlocked (same pattern as public holidays). Reshape `HrOverview` around desk panels using extended `loadHrDashboard` data. Add pure helpers for WA templates, leave-this-week partitioning, multi-type balances, and booking overlap checks; wire client sheets into `HrLeaveStatusActions`.

**Tech Stack:** Next.js App Router, Supabase, Vitest, next-intl, existing HR/Marketplace modules.

**Spec:** `docs/superpowers/specs/2026-08-20-hr-strong-design.md`

## Global Constraints

- Solo+ tiers: `micro` | `sme` | `enterprise` unlock HR pillar (`lib/auth/entitlements.ts`).
- No WhatsApp Business API — CTC `wa.me` only.
- No new desk aggregate tables.
- Leave approve with booking overlap: **warn + confirm**, not hard-block.
- Marketing Strong is out of scope (separate PR).
- Prefer TDD: failing Vitest → implement → pass → commit per task.
- Branch: `feat/hr-strong-core` from updated `main` (or current integration branch if Phase 1 not merged yet).

```ts
import { hasPillar, type Pillar } from "@/lib/auth/entitlements";
import type { TierKey } from "@/lib/settings/plans";

export function staffPortalIncludedForTier(tier: TierKey): boolean {
  return hasPillar(tier, "hr");
}

export async function hasStaffPortalAddon(businessId: string): Promise<boolean> {
  const supabase = await createSupabaseServerClient();
  const { data } = await supabase
    .from("businesses")
    .select("tier")
    .eq("id", businessId)
    .maybeSingle();
  const tier = (data?.tier as TierKey | undefined) ?? "starter";
  if (staffPortalIncludedForTier(tier)) return true;
  return hasActiveAddon(businessId, HR_STAFF_PORTAL_ADDON_SLUG);
}
```

- [ ] **Step 3: Implement `lib/hr/desk.ts`**

```ts
export function dateInRange(ymd: string, start: string, end: string): boolean {
  return ymd >= start && ymd <= end;
}

export function rangesOverlap(
  aStart: string,
  aEnd: string,
  bStart: string,
  bEnd: string,
): boolean {
  return aStart <= bEnd && bStart <= aEnd;
}

export function partitionLeaveForDesk<
  T extends { start_date: string; end_date: string; status: string },
>(leaves: readonly T[], todayYmd: string, weekEndYmd: string) {
  const approved = leaves.filter((l) => l.status === "approved");
  const today = approved.filter((l) =>
    dateInRange(todayYmd, l.start_date, l.end_date),
  );
  const thisWeek = approved.filter((l) =>
    rangesOverlap(l.start_date, l.end_date, todayYmd, weekEndYmd),
  );
  return { today, thisWeek };
}

export function selectExpiringDocuments<
  T extends { expires_at: string | null },
>(docs: readonly T[], todayYmd: string, withinDays: number): T[] {
  const end = addDaysYmd(todayYmd, withinDays);
  return docs
    .filter((d) => d.expires_at && d.expires_at >= todayYmd && d.expires_at <= end)
    .sort((a, b) => (a.expires_at! < b.expires_at! ? -1 : 1));
}

function addDaysYmd(ymd: string, days: number): string {
  const d = new Date(`${ymd}T12:00:00`);
  d.setDate(d.getDate() + days);
  return d.toISOString().slice(0, 10);
}
```
